# 视觉更新边界与角色增量的匹配对照

状态：DRAFT / PREPARATION_ONLY。原视觉起点六端仍有两端训练；本计划未注册、未执行M0、未启动正式训练。下一阶段启动前必须接收原六端完整报告，并完成独立代码审查。这里不修改原实验、门槛、来源、种子或失败记录。

## 问题与待检验主张

源码核查发现当前新架构完全冻结视觉主干，而作者Signal默认允许视觉参数以5e−6更新。M1能够更新共享表示，其梯度链没有被整体切断。原24项模块消融与独立global-only实验还说明，共享适配经常解释大部分收益。因此先验证实际训练边界，而不再追加新模块。

- C1：固定结构和其他训练条件，开放视觉参数的小学习率更新能否改善未知身份检索？这是训练控制，不是算法创新。
- C2：在相同视觉更新边界下，完整角色路径能否超出独立训练的共享global控制？不能将微调收益全部归给角色。
- 排除的解释：新模型只是因为能够更新更多预训练参数而提高；或者“局部输出”其实只是联合训练的global修正。

本计划固定原已训练纯ReID基线来源，未按当前两项公开视觉成绩选取新起点；不在本阶段重新搜索公开/本机/发布权重。保留原三份纯基线作为预训练权重。其上游ReID训练成本与camera状态必须披露。

## 十二项完整对照

每个数据集执行同一2×2矩阵，RGBNT201、RGBNT100、MSVR310共12端，全部seed42、新建训练、完整50轮。

| 视觉更新 | 读出 | 回答的问题 |
|---|---|---|
| frozen | global_only | 新FP32存储合同下的共享适配控制 |
| low_lr | global_only | 视觉微调本身的效应 |
| frozen | roles | 同合同下的完整角色控制 |
| low_lr | roles | 微调条件下的角色增量及交互 |

`global_only`从同一完整初始化中仅保留backbone、neck、classifier，不运行CNN/Transformer/Mamba和角色读出。四端共有backbone与分类头初始张量逐项相等。不能把角色模型同权重截取global当成这条独立训练控制。

## 唯一干预与共同条件

- `low_lr`仅开放`clip_vision_encoder.base.*`的152个视觉参数，学习率固定5e−6。camera和其余Signal参数继续冻结，SIM/AlignM不存在。不给新模块增加loss或改变采样。
- 所有四端的视觉参数存储统一FP32，AMP前向规则一致。必须新跑frozen控制，旧结果不替代新的dtype合同。
- 新参数仍使用当前配置NEW_MODULE_LR、AdamW、weight_decay、五轮warmup与50轮cosine；视觉组使用相同日程倍率。不是作者Adam/采样流程的完整复现。
- 保留STATIC、full128 Patch memory、独立FP32注意力、M1第4/8/12层、context query、1536D区域读出、无辅助ID、无M3。global_only只省去角色计算。
- 原数据入口：batch64/K8、同增强/seed42/分类标签，CE smoothing0.1、Triplet margin0.3。完整正式query/gallery及原过滤：201/100同身份同camera；MSVR同身份同时间段。保留gallery干扰身份。训练身份与正式查询身份按已有protocol隔离，不用全训练起点冒充内部身份OOF。
- 每项跑满50轮，以逐轮官方fused mAP最高的一份权重选点、平分时取后轮，四项指标来自同权重严格重载。披露官方集用于选轮和历史方法选择，不称未消费的独立测试。

## 实现合同

新增独立入口`tools/run_visual_update_control.py`，复用原构建器、生产Mamba、loader、Triplet和作者正式计分。原运行源文件不修改。

当前checkpoint排除整个Signal，不能保存更新后的视觉权重。因此新入口保存完整模型state并strict重载；原纯基线只读。保留原冻结断言，只将允许更新的视觉152参数从冻结比较中排除。实际M0要求全部选定可训练张量都有有限且非零梯度、low_lr视觉确实变化、frozen视觉不变、camera及非视觉状态不变、八批后严格重载输出一致。

不增加fallback、异常吞掉、自动减batch或OOM重试。若真实M0失败，保存原日志，定位原因后修改明确合同；不能把失败端直接跳过。资源/有限值检查沿用已有实验合同，不新增假设性防御逻辑。

## 固定解释与晋级边界

两类效应分别报告，不能选择更好分母或跨epoch拼列。视觉控制的支持要求low_lr−frozen在两种读出下三个数据集mAP均>0、R1均≥0，且RGBNT201/MSVR310各至少0.5mAP。角色支持要求roles−global_only在low_lr条件下三个数据集mAP均>0、R1均≥0，且201/MSVR各至少0.5mAP。规则任一不满足即保持失败；不扫描LR、换种子挽救。同预算不等于相同FLOPs，角色训练代价另报。

若只有global-only微调有效，仅是C1的部分证据，注册的整体视觉支持门仍失败，C2未获支持；方法主张应收缩，不把普通微调包装成新颖角色协作。如果两者均负，训练边界假设失败，回到表示/职责问题。任何局部门通过都不等于三数据集超过baseline及经资源/协议注明的当前强方法目标完成。稳定性/论文结论后续仍需匹配种子验证，本阶段单seed不声称稳健。
