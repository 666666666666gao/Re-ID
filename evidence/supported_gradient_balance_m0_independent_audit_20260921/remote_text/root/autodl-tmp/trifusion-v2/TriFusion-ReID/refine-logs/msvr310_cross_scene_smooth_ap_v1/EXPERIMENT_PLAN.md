## 唯一待验证主张

在原 V8 三角色、当前坐标和历史候选完整反传不变时，将 fused Smooth-AP 的关系与均值定义改为合法跨场景检索关系，能否改善未知身份的完整图库排序。标准 Smooth-AP 与场景过滤均为已有机制，本实验不声称其单独原创。

原 Smooth-AP 完整 Q1 增益 +0.343455 mAP，未晋级。完整来源覆盖分析显示来源排序改善；完整固定终态梯度诊断显示真实 fused 梯度，并非完全没有信号。两端加载各自终态，不能据其梯度比推出 loss 倍率。此次不调 tau、权重或失败版本终点。

来源支持沿用 evidence/smooth_ap_cross_scene_support_20260909/smooth_ap_cross_scene_support_20260909.json，不重复运行普查。三折预热后各12480次 anchor 曝光中，具有候选内跨场景正例的分别5144/5176/5056；零合法 anchor 的 batch 分别1/1/2，共4/585。它们是重复训练曝光，不是独立图片或梯度贡献统计。

## 两端与精确定义

- control：原标准 Smooth-AP，全部同身份位置为正例，只排除当前 self。
- cross_scene：同身份且不同 scene 为正例；所有其他身份为负例，包括同 scene。相同身份、相同 scene 的位置完全排除本项排名分子和分母，不能改作负例。
- scene 使用现有 MSVR310 loader 的真实 scene 字段与评价过滤定义，不替换成 camera。
- 候选端对有合法正例的当前 anchor 取等权均值，loss = 1 - mean(AP)。无合法正例的 anchor 不参与此项均值，但保留其他13项监督，并作为其他身份的候选干扰项。
- 已观察到整个 batch 无合法 anchor：本项返回连接 current/history 距离图的精确零，产生零导数；不改用同场景正例，不改采样，不跳过其余监督或 optimizer 更新。逐步记录 eligible anchor 数与零批次。
- 当前同记录的不同增强视图仍按既有位置合同保留；历史保持唯一记录与排除当前记录副本。候选端同场景同身份过滤自然排除这些重复正例；负身份的不同当前视图仍参与排名。
- 每个正例自身比较排除；tau=0.01，余弦等价分数 s=1-d²/2，fused项权重1。
- 两端计算同一组 hard、standard AP、cross-scene AP 供完整核验；实际只选择规定目标。前65步均沿用原批内 hard，之后切换各自 AP；历史入队/首次参与时刻保持原规则。

本干预同时改变排名关系和 eligible-anchor 分母，属于一项明确的协议定义；不能把效果单独归因于删除容易正例。候选内 AP 也不是完整官方 mAP 的无偏估计。

## 执行顺序与最低证据

1. T0：独立标量与有限差分验证 standard/cross AP；检查self、同身份同scene忽略、同scene负身份保留、无正例anchor继续作负候选、全零eligible图连接、位置置换及历史两侧导数。绑定原来源支持记录；不重做无关诊断。
2. 独立代码审查：在部署前核对协议、三个目标调用位置（当前、历史leaf、direct完整图）与CPU验证器使用同一定义。修复真实问题后再进入GPU。
3. M0：沿用三折两端各8更新（2步预热）和fold0两端100步固定batch，共248更新。203/203累计非零、无overflow、Signal冻结、严格重载输出一致、原校正过拟合比≤0.1。每端首个实际历史组direct/VJP误差≤0.005；报告历史角色贡献。不把单组见证扩大为全程独立梯度重建。
4. M0_CPU：全部距离及身份/scene重算三种目标、eligible mask/count、AP、14项账本和零批次；AP绝对误差≤2e-6。通过后执行完整六端Q1及完整CPU终态，再独立审计。
5. Q1失败则封存并分析完整记录；通过后才按既有边界推进后续主结果。当前不启动消融矩阵或官方测试。

主张的最低支持是预先规定的完整配对与Signal门通过；仅来源AP下降、增加跨场景比重或工程门通过均不足。若覆盖下降或角色受损，只否定本定义，不将所有协议感知目标宣判无效。
