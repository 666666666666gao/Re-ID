# MSVR310 来源实例覆盖 V1：固定配对实验

登记日期：2026-09-07；依据完整来源普查提交2a9b618。此计划在任何本轮真实模型前向/更新之前冻结。

## 假设与边界

唯一主假设：MSVR310原三角色训练的批内fused Triplet遗漏部分有效实例关系；扩大为当前batch加有限历史source实例，在不改变网络、其余损失权重和推理表示的条件下，可改善未知身份的完整scene图库检索。

完整来源普查已经证明：普通终点固定增强跨scene fused94.956353，333/1200query成员有部分正例误排序，300原型正确但部分实例排序错误；纯银行同样有327个未解决query。这区别于RGBNT201来源几乎饱和，但还未证明当前batch遗漏了哪些关系，也未证明历史特征足够新鲜。本次直接记录这两项，而不是把原型差异当成已证明的记忆收益。原型统计同时涉及正/负实例平均，不能只归因于负例。

这是独立实现XBM思路的项目化测试，不是原创模块或XBM原论文完整复现。原文：https://arxiv.org/html/1912.06798 ，§3.2/3.3明确讨论表示漂移、预热和停止梯度队列。采用其思想；不复制作者CC-BY-NC代码。新的训练职责、样本保留策略等原创主张，本次均不提出。

## 唯一训练干预

- 原V8平行CNN/Transformer/Mamba、冻结完整Signal/CLIP、固定7680D融合与五个独立检索输出不改。使用原plain V8 backbone；本轮不启用style包装，也不启用Router、联合头、原型分类、责任loss或Smooth-AP。
- 原七组ID/Triplet共14项、全部权重和0.3欧氏Triplet间隔不改。control使用原批内fused Triplet；candidate只将这一项的hard-positive/hard-negative候选扩展为当前batch与历史实例的并集。
- 当前batch所有表示保留梯度；历史表示detach。保留原批内重复增强视图和排除对角线规则，不改变原采样器；历史队列按真实record_index保留最新视图，排除当前batch任意记录的历史副本。合法class0和同身份跨camera/scene始终是正身份，不能把不同camera当负标签。
- 训练正例继续遵循原Triplet的真实同身份合同（任何scene、排除自身记录历史副本）；负例为不同真实身份。另单列历史跨scene正关系曝光。正式评价严格排除同身份同scene，不能改成same-camera。
- 每个fold/端单独空队列。最多512个唯一记录、最多8次更新年龄；先用原5epoch/65step预热，step65零起始开始入队，下一步才有历史候选。容量与年龄是预先固定的工程预算，不从Q1或official扫描。无额外可训练参数、EMA编码器或额外训练图像。
- 两端都计算同样的历史候选、shadow expanded loss、缓存更新与漂移诊断；只有candidate将expanded loss用于更新。当前batch Triplet仍单独记录。相比追加新loss，这样保留原权重总量，控制端也承担同等诊断开销。

## 真实学习信号与缓存核查

逐步保存实际sample索引、全三模态像素SHA、所有历史记录/真实身份/scene/年龄/保存步，全部批内和历史欧氏距离矩阵。CPU独立重放每个step的FIFO去重/年龄/排除规则、正负mask、hard候选、hinge及原14项总loss算术。完整矩阵只留远端。

记录历史正负对、跨scene正对、新的更难正例/负例anchor数、历史负例违反当前hard-positive+0.3的数量、联合候选反序与hinge数量。记录实际fused角色部分的新增梯度，并在首个有效历史干预处对同一encoder参数计算expanded减原Triplet的真实梯度，三角色均须非零；不得把只多了一层detach当成新监督。

每个训练epoch保存首个真实增强batch的像素、当时RNG与fused单位表示，在8次更新后重放同一个batch/RNG。临时缓冲区与全局RNG全部恢复，0额外更新，两端成本匹配。输出64个实例L2漂移；不是重新随机增强后的特征差，也不是未见身份泛化证明。M0先验证无更新的同像素/RNG重放逐位一致。年龄上限不自动保证慢漂移，本次完整分布作为解释证据，不按中间漂移结果改年龄/预热。

## 固定预算与评价

继承已完成MSVR配对配置的Signal epoch50/source初始化、seed42、B64/K8、128×256、workers4、AdamW lr0.00035/wd0.0001、5epoch预热与20epoch终点。三折各672/683/709source记录，103/103/104source身份，原完整采样索引逐step核对。候选和控制均从相同原初始化新训，不复用M0或之前control终点。

Q1共6端×260=1560更新；固定全部600query、60合法query身份、1032条fold gallery记录，保留全部无正例干扰身份。Signal特征及距离必须逐位等于各折B0。已有精确Signal推理入口和56线程CPU距离路径继续保留，训练/冻结前向4线程；不让对照恢复旧数值错误。

两组现有科学条件全部保持：相对matched control，以及相对Signal，各自要求fused≥1pp、各fold非负、三个完整角色非负、身份bootstrap下界正、fused严格最高（包含Signal）。只有完整两组均通过才晋级；不得重新定义融合最高、挑checkpoint或以M0通过认定有效。

## M0和执行顺序

1. T0：完整780个采样batch的队列准入CPU重放，独立数学fixture（class0、重复记录、过期、空队列、完整hard-triplet与梯度）；0模型/更新。
2. M0：3fold×2端×8真实capacity更新，capacity队列预热2步以实际触发新路径；各端全部203张量真实梯度、冻结状态、0overflow、单卡显存、严格compact checkpoint重载及五输出逐位一致。初始同像素零更新重放必须逐位一致。
3. 原固定100步过拟合门每端一次，仍以原理论ID下界的excess ratio≤0.1为门。固定batch反复出现时，其所有历史副本被合法去重排除，因此该门检验原主任务；记忆路径的实际新增监督由上述多batch容量检查验证，不能把固定batch过拟合冒充记忆泛化。
4. M0总248更新，全量CPU通过后执行完整Q1；Q1结束再独立全量CPU核对6权重、1560步缓存/关系算术、完整距离/排序、AP/CMC/身份统计与全部晋级条件。原失败即停，保留原始日志/PID；不因观察超时重复启动。

M0约7–10分钟，完整Q1约35–50分钟，按实际epoch速度修订。每端Q1增加20×64=1280次固定像素漂移前向，六端7680；M0容量及过拟合另有8×64=512次，预检和重载前向单列。额外forward不改变优化步数，效率报告包含全部成本。

预计总增量<1.8GiB：M0/Q1 compact权重约0.4GB、检索数组和全部距离诊断矩阵。启动至少3GiB，当前主盘约5.46GiB；保留当前初始化、全部必要最终权重和历史复核。复用刚完成完整Q1/来源普查的tri_reid环境，未新建或修改环境，不以新import冒充环境认证。

## 交付与失败解释

完整原始训练/缓存/漂移记录、6端结果、全部query和身份变化、真实参数/显存/时间、paired与Signal条件各自PASS/FAIL。旧MSVR style Q1_FAIL和其他数据集结果保持封存。source改善不能代替heldout，更不能与论文official表直接相减。

若新增有效关系稀少，当前实例覆盖假设缺乏有效监督；若存在关系但历史漂移大，报告近似误差风险；若工程和新增梯度均通过而Q1退化，封存这一固定实例记忆配置。均不即时扫容量、年龄、margin、epoch或融合权重救回。
