# 原始目标梯度与 AdamW 更新的解释边界

本页是当前固定来源诊断的解释补充，不修改诊断合同、运行代码或已绑定的分析器，也不提出新的损失倍率。完整1560批结果仍须全部完成并核验后再解释。

**实测对象。** `tools/probe_msvr_smooth_ap_objective_gradients.py:89`只选取189个可训练`encoder.*`参数，逐角色计算完整fused项与其余13项的导数。诊断固定终点模型，恢复入口buffer，采用固定AMP scale256，不创建优化器。这些范数/点积回答当前参数处损失的局部导数问题，不能还原原训练的逐步更新轨迹。

**实际更新路径。** `tools/train_msvr_smooth_ap.py:77`创建AdamW（当前基合同学习率3.5e-4、weight decay1e-4；每epoch另有既定调度）。历史候选VJP先加入当前梯度，再unscale、检查有限性，最后一次`scaler.step`/`scaler.update`（239–245行）。这段路径没有梯度裁剪。诊断的189参数不是整个优化器参数列表，后者还包含可训练分类头。

**可恢复范围。** trainer通过`tools/train_msvr310_source_style.py:164`保存角色state、冻结基线alias和绑定信息；该保存函数没有AdamW的动量/平方动量或GradScaler状态。终点模型不能据此重建历史预条件器。现有原训练日志记录scale与学习率，但不是优化器每个参数的完整状态。

AdamW用历史一阶/二阶矩及逐坐标分母形成更新，并单独处理权重衰减。因此一般不存在“原始梯度范数比例等于实际更新贡献比例”的关系。[PyTorch 2.5.1官方实现](https://github.com/pytorch/pytorch/blob/v2.5.1/torch/optim/adamw.py)。下面是自行推导的数学示例，不是项目测量：若首步两项梯度为gF=(1,0)、gO=(0,10)，总梯度为(1,10)，忽略epsilon和weight decay时，Adam偏差修正后的首步为(-eta,-eta)。原始范数比0.1没有使两个坐标的更新幅度呈1:10。这个例子也不定义各损失的反事实贡献，因为改变总梯度会改变后续矩状态。

完整结果报告继续使用既有norm、cosine、重复噪声和数值恒等式，按固定参数局部证据表述。可以检查fused项是否产生有效导数、与其他监督的方向及规模是否不同；不能将其百分比称为泛化贡献或AdamW更新份额，也不能仅靠负余弦就决定PCGrad或按范数倒数放大损失。没有新增优化器回放、GPU前向、训练或官方测试访问。官方源码原文仅在临时目录保存，项目保留本说明和来源哈希。
