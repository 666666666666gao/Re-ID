# MSVR310 当前历史坐标更新：固定配对实验 V1

登记于2026-09-08，依据已完成并公开的完整来源新鲜度诊断（9c8c6b7）。本计划在新实验任何训练或heldout前固定，不修改旧实例记忆或新鲜度诊断结果。

## 唯一主张与边界

在完整来源诊断中，陈旧缓存与当前角色重编码相比，在实际记忆更新轨迹改变约32%–34%的困难负例选择，Transformer诊断梯度平均余弦约0.660–0.674；终点则接近1。因此下一项唯一干预为：相同历史记录/视图/年龄/停止梯度边界下，使用当前角色重新编码的坐标代替缓存坐标进行扩展Triplet更新。

检验的是这种坐标替换能否带来未知身份检索收益。它不是新的XBM或GradCache原创主张，不将来源梯度差异当作检索提升。候选与控制都执行完全相同的历史字段重编码、旧/新坐标诊断及重复反传噪声检查；不允许把更多计算混作方法收益。

不增加可训练参数、EMA、历史候选反传、全候选anchor、归一化补偿、统计扰动、Router或联合头。不扫描年龄、margin、损失权重、checkpoint或seed。单seed42和多次开发OOF的限制保留。

## 两个更新端

- `control`：预热后将原fused Triplet替换为当前batch加陈旧历史坐标的expanded Triplet。
- `fresh_memory`：同样替换，但历史坐标由当前角色参数、相同冻结anchor/reference/baseline字段和历史入口RNG重编码。
- 两端都执行旧/新重编码与诊断；只在实际更新时选择不同历史坐标。其余13项ID/Triplet及全部权重相同。Control在本合同中代表陈旧缓存更新，不再代表原批内更新。
- 当前batch peers保留梯度，历史候选两端都detach；fresh memory不等于所有历史图参与反传的大batch。新增诊断使用同一角色参数，不比较不同角色参数向量。
- 单个历史记录保留最新增强视图、相同批内最后位置，capacity512，最大年龄8次更新；排除当前记录的全部历史副本。真实相同身份始终正类，合法class0不被过滤。
- 原始冻结字段复用路径由完成诊断验证，本实验还逐端重新执行真实B64零更新bitwise检查；RNG和buffers逐次保持，不改变训练模式或BN状态。

## 固定训练与评价

继承MSVR source Signal epoch50、原角色初始化seed42、三折source672/683/709记录和103/103/104身份、B64/K8、128×256、workers4、AdamW3.5e-4/wd1e-4、20epochs×13updates及5epoch预热65步。双方从初始化重新训练，不接续诊断或M0终点。逐步核对全部780采样batch，两端三模态增强像素SHA必须完全一致。

Q1全部六端1560更新，全部600query/60合法query身份，分折gallery合计1032记录，保留无正例干扰身份。使用已有MSVR scene/time过滤、精确Signal推理与56线程距离路径；冻结Signal特征/距离应逐位等于既有B0。官方图片读取0；不在当前官方已消费集调参。

保持两组原有五项门：相对本次matched陈旧端，以及相对Signal，分别要求fused增益至少1pp、各fold非负、三个完整角色非负、身份聚类bootstrap下界正、fused严格最高（包含Signal）。两组全通过才晋级。旧普通batch端和旧失败成绩只作有条件背景，不拼接跨次差值或重新解释旧门。

## 执行门与预算

1. T0：固定源码/输入SHA、全部780batch候选准入与年龄重放、既有expanded Triplet独立CPU数学检查，0模型前向。
2. M0 capacity：3fold×2端×8真实更新，预热2步；每端实际重编码零更新逐位一致、非零历史候选、新旧参数梯度差异大于重复噪声见证、203/203梯度、0overflow、冻结状态不变、compact严格重载和五输出逐位一致。
3. 过拟合：fold0两端各100固定batch更新，原excess-loss ratio≤0.1门不变。当前记录排除使历史集合为空，此门检验主任务，历史路径由capacity门验证。M0合计248更新，全CPU核查后方可Q1。
4. Q1：固定20epoch全部六端、strict checkpoint reload再完整检索。无中间fold停止或改参。工程失败停止并记录；不会因观察超时重启。
5. Q1 CPU：核对全部训练距离、旧/新坐标距离、实际更新loss、候选与年龄、梯度运行见证、六终点、全部排序/AP/CMC/身份统计及所有原门。CPU不宣称独立重算模型梯度。

两端额外计算匹配：全部历史组重编码（每组原B64以保持RNG路径），逐step新旧诊断和重复反传，保留原每epoch一次固定视图漂移检查。Q1每端重编码预期97600条（含64零更新验证），另保留20×64=1280漂移记录前向；真实次数/峰值/时间单列，不声称免费或推理节省。

预估M0约10–15分钟，Q1和全CPU约2–3小时，以真实速度修订。持久screen→T0→M0→CPU→Q1→CPU，观察180–300秒或预计里程碑。启动至少3GiB主盘空闲，预计新增<1.8GiB；此前实查4.59GiB，启动前再查。初始化、必要终点、原图、二进制矩阵留远端，日志与报告同步。复用已完成完整1560步诊断的tri_reid环境，不安装/重建环境，不将其称为新环境认证。
