## 三项核心创新（查新前工作冻结版）

1. **AHCR — Asymmetric Heterogeneous Cyclic Refinement**：CNN 分支输出局部显著性与多尺度纹理，指导 Transformer 选择身份相关 Token；Transformer 的全局身份上下文调制 CNN 通道并初始化 Mamba 状态；Mamba 的长程状态用于恢复/补全低质量 Token，再反馈给 CNN 与 Transformer。每个阶段均双向交换低秩 relay token，每个分支都有独立 embedding、分类头和度量监督。
2. **CRCR — Counterfactual Reliability-Complementarity Router**：融合权重不仅估计“分支是否可靠”，还学习“加入该分支相对其余分支能带来多少边际信息”。训练期通过 leave-one-branch-out 正类 margin/loss 差构造 stop-gradient 反事实教师，测试时仅由特征质量、分支分歧和模态可用掩码预测权重。
3. **RPMT — Role-Preserving Mutual Teaching**：用置信度选择的身份分布、样本关系和原型关系做三方互教，同时保留 CNN/Transformer/Mamba 的局部、全局、长程专属辅助目标与去冗余约束，避免三路蒸馏成同一个表示。

以上名称和“首次”措辞必须等 `docs/RESEARCH_AUDIT_2026-08-31.md` 查新结果后再冻结；负面查新会触发改名或机制收缩，不制造新颖性结论。

## Experiment Blocks

### Block 1：数据、指标与 DeMo 基线奇偶校验

- Claim tested：后续比较建立在正确数据协议和可信基线之上。
- Why this block exists：RGBNT201 官方实现的 query/gallery 都指向 `test`，必须确认相机过滤和 evaluator 与论文一致。
- Dataset / split / task：RGBNT201 `train_171`；官方 `test` 协议。
- Compared systems：官方 DeMo 配置；官方代码在现代 CUDA/PyTorch 下的兼容运行。
- Metrics：mAP、Rank-1/5/10；样本数、身份数、三模态配对；参数量、FLOPs。
- Setup details：CLIP ViT-B/16；50 epochs；有效 batch 64；Adam；LR 3.5e-4；AMP；微批次按 8 GB 显存下探并用梯度累积保持有效 batch。
- Success criterion：数据审计全通过；evaluator 小样本手算回归通过；DeMo 单种子与论文数值差不超过 0.3 pp，否则先诊断，不进入主模型结论。
- Failure interpretation：环境、预训练权重、数据版本、随机性或 evaluator 不同；不得把不一致基线当作弱对手。
- Table / figure target：实现细节与复现表。
- Priority：MUST-RUN。

### Block 2：TriFusion 主结果

- Claim tested：完整三模态下，异构协同模型优于 DeMo 和晚期融合。
- Why this block exists：这是核心 anchor result。
- Dataset / split / task：先 RGBNT201；通过门后扩展 MSVR310、RGBNT100。
- Compared systems：DeMo；CNN-only；Transformer-only；Mamba-only；三分支平均；三分支 concat+MLP；完整 TriFusion。
- Metrics：mAP、Rank-1/5/10；三种子均值±标准差；参数量、训练/激活 FLOPs、吞吐、峰值显存。
- Setup details：相同输入尺寸、数据增强、预训练资源和 evaluator；不使用 reranking、TTT、文本或测试标签；主表固定种子 42/3407/9199。
- Success criterion：至少一个主数据集严格超过当日核验的同协议纯视觉静态 SOTA；RGBNT201 暂定门槛为 mAP > 85.3 且 Rank-1 > 87.9，最终以查新审计为准；其余数据集不出现不可解释的大幅回退。
- Failure interpretation：若仅 ensemble 有益而各分支不改善，C1 不成立；若只在一个小数据集涨，需限制泛化主张。
- Table / figure target：主表 Table 1、架构图 Figure 2。
- Priority：MUST-RUN。

### Block 3：三项创新隔离与容量控制

- Claim tested：AHCR、CRCR、RPMT 均有独立、机制一致的贡献。
- Compared systems：无协同；仅 AHCR；AHCR+普通 soft gate；AHCR+CRCR；AHCR+CRCR+普通 KL；完整 RPMT；matched-parameter MLP/Transformer control；更多参数但无协同 control。
- Metrics：主指标、每分支独立 mAP/Rank-1、错误交并/Oracle routing 上限、router 边际贡献相关系数、表示 CKA/余弦冗余度。
- Setup details：先单种子决策，晋级配置再补三种子；任何选择仅用训练/验证预注册口径，不读取测试标签调参。
- Success criterion：每项核心机制相对直接前身带来可复现增益；完整方法优于容量匹配控制；三个分支均有非零梯度、非塌缩利用率和独立判别能力。
- Failure interpretation：无独立增益的模块从主创新中删除，不靠打包后的总增益保留。
- Table / figure target：Ablation Table 2；分支互补图 Figure 3。
- Priority：MUST-RUN。

### Block 4：缺失模态、质量退化与跨数据集

- Claim tested：CRCR 与 RPMT 在真实不完整/低质量输入下有价值。
- Dataset / split / task：RGBNT201 六种固定缺失组合；模糊、遮挡、过曝/欠曝、噪声；MSVR310/RGBNT100 完整与缺失协议。
- Compared systems：DeMo、DENet/PDRNet 的公开同协议结果（能复现则优先复现）；完整 TriFusion；去掉 CRCR/RPMT。
- Metrics：六组合平均 mAP/Rank-1、最差组合、退化曲线面积、完整模态性能保持率、ECE/路由校准。
- Setup details：退化强度在训练前冻结；报告每种模态和组合，不只报告平均值。
- Success criterion：完整模态不牺牲；缺失平均和最差组合均改善；router 权重随可控退化方向合理变化。
- Failure interpretation：若仅训练见过的 mask 有效，主张限于 modality-dropout 鲁棒性而非任意缺失泛化。

## Risks and Mitigations

- **风险：三个分支只是参数堆叠。** 缓解：参数/FLOPs 匹配控制、分支独立指标、错误互补与 leave-one-out 贡献。
- **风险：跨分支交互导致同质化。** 缓解：角色专属目标、relation-level 而非 raw feature 全对齐、去冗余约束。
- **风险：router 学成固定模态/固定分支映射。** 缓解：质量扰动、modality dropout、熵/负载审计、反事实边际监督。
- **风险：SOTA 使用更强 DINOv3 等预训练。** 缓解：分别报告同预训练公平表与开放资源上限表；必要时新增同一 DINOv3 tokenizer 的公平变体。
- **风险：单次随机种子偶然增益。** 缓解：决策阶段单种子，最终主结果固定三种子并报告方差。
- **风险：官方代码/README 不一致。** 缓解：固定提交、记录补丁、数据与权重哈希、先完成 baseline parity。
