# Training origin and trainable-boundary source check

This is a read-only source comparison prepared while the registered nine cross-depth endpoints finish. It registers no new model, initializer, configuration or training job. The seven author files are pinned to MambaPro commit `f9ee6f60e58f21f3da1c8fd0e659fcc8db9ab149`; their original downloaded bytes, URLs and SHA256 values are in `SOURCE_CHECK.json`. No author checkpoint bytes or training process were inspected.

The current TriFusion path constructs a module-free Signal model and then strictly reloads every saved dataset-trained pure ReID state entry. `tools/run_correspondence_roles.py:35` passes `plain_baseline=True`; `tools/official_three_dataset_model.py:69` loads the complete state with strict matching. `CrossLayerAdaptedCLIP` subsequently freezes all Signal parameters. Consequently, the current cross-depth experiment is a second stage on an already trained ReID representation. The public CLIP file is used during construction, but that fact does not make the final loaded backbone an untouched public CLIP initialization. The saved pure baselines remain necessary and are not overwritten.

The pinned [MambaPro loader](https://github.com/924973292/MambaPro/blob/f9ee6f60e58f21f3da1c8fd0e659fcc8db9ab149/modeling/make_model_clipreid.py) uses a hard-coded relative CLIP filename. Its actual file bytes and identity cannot be established from that filename. The normal [training entry](https://github.com/924973292/MambaPro/blob/f9ee6f60e58f21f3da1c8fd0e659fcc8db9ab149/train_net.py) constructs the model and proceeds to optimization without an explicit dataset-trained ReID checkpoint reload. This code path differs from our strict second-stage reload; it does not prove that our initialization is the cause of poor retrieval.

The author [freeze function](https://github.com/924973292/MambaPro/blob/f9ee6f60e58f21f3da1c8fd0e659fcc8db9ab149/modeling/clip/LoRA.py) retains visual parameters whose names contain `adapter`. The prompt parameters also use that prefix, so “frozen CLIP” does not imply frozen prompts. The external camera embedding is created after the visual freeze in [model construction](https://github.com/924973292/MambaPro/blob/f9ee6f60e58f21f3da1c8fd0e659fcc8db9ab149/modeling/make_model.py). Our complete Signal freeze includes its camera embedding. Static construction supports this distinction, but actual third-party optimizer membership and runtime gradients were not replayed.

The author [visual path](https://github.com/924973292/MambaPro/blob/f9ee6f60e58f21f3da1c8fd0e659fcc8db9ab149/modeling/clip/model.py) carries prompt state across visual blocks, and loads the CLIP state with non-strict matching to allow new parameters. Our current recurrent condition carries role-anchor states across captured depths 4/8/12 after shared encoding; it is not the same as inserting persistent prompts through every attention block. The author [RGBNT201 configuration](https://github.com/924973292/MambaPro/blob/f9ee6f60e58f21f3da1c8fd0e659fcc8db9ab149/configs/RGBNT201/MambaPro.yml) trains 60 epochs. Our current contract is complete50 with official mAP-best selection.

This follows from one2,361,600-parameter parallel FFN, four590,976-parameter prompt transforms, and9,216 prompt-vector parameters per block. It is not a third-party runtime parameter/gradient audit, a full-model author count, or a claim that every declared tensor is active in each forward. The two adaptation schemes are not capacity-matched. This does not establish insufficient capacity as a cause, nor justify copying a larger module without a separate controlled hypothesis.

These are distinct controls: training origin, camera parameter boundary, where state enters the backbone, module capacity, and training budget. Changing them together would not identify which change helped. Current nine-endpoint results must finish before choosing another intervention. No predicted score, reproduction claim, new baseline denominator or causal explanation follows from this source note.
