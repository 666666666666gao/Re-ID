# 角色完整 Patch 内容读取：配对实验计划

日期：2026-09-30。状态：训练前登记；CPU 结构检查已通过，尚无正式结果。

## 问题与主张

原24端消融和独立 global-only 已完成；201、100的角色额外增量很薄。小邻域内容查询、区域读出、身份上下文查询、额外局部身份监督、跨层状态和视觉提示均已有完整结果，不能重新列成未尝试方向。最新 reset/carry 提示六端验收后，carry 在201的 mAP 条件差为负，预登记的后继 global-only 门失败，保持封存。

**唯一新干预：**每个角色槽位通过同一套可训练 Q/K/V/输出投影，只能读取最近9个 Patch，或可以读取完整128个 Patch。待检验主张是，角色读取范围的限制妨碍了额外身份证据形成；完整内容支持是否有用应由匹配局部控制决定。注意力及完整内容读取已有先例（[DeMo](https://github.com/924973292/DeMo)、[IDEA](https://github.com/924973292/IDEA)），本计划不主张其原创。

反主张：增加投影参数、改写读出或加强 global 适配本身就解释了收益。两端参数和初始化相同，只有注意力支持掩码不同；不能以完整端相对历史弱分母的差替代两端配对差。

## 固定实验合同

| 项目 | 两端共同设置 |
|---|---|
| 起点 | 各数据集已保存纯CLIP ReID权重；201/MSVR基线50轮，100基线30轮。不是零样本CLIP或作者完整Signal |
| 模型 | M1第4/8/12层共享适配和角色快照；CNN、Transformer、真实Mamba；身份上下文查询、16槽位、128内部宽度、1536维最终向量 |
| 位置 | 固定4×4参考槽位，两端不学习偏移；最近邻距离用Patch中心间隔单位，稳定排序确定最近9个Patch |
| 内容 | Q来自槽位向量和样本global上下文；K来自归一化角色Patch，V来自角色Patch。global只调制查询，不复制进局部值 |
| 对照 | local_memory：128个候选中只允许最近9个；full_memory：同样的Q/K/V计算允许128个。相同支持buffer保存在两端state，模式不改变参数构造 |
| 协作及读出 | 原CNN→Transformer→Mamba桥接、同参数正反Mamba扫描；保留原模态×槽位组读出和global加性融合 |
| 训练 | seed42；M3关闭、额外身份头关闭；原ID+Triplet、同loader/增强/AMP/AdamW/学习率日程；每端角色阶段完整50轮 |
| 选点 | 每轮官方评价，以最高fused mAP选同一checkpoint；其他指标随该checkpoint，完成50轮后严格重载全量评价 |
| 协议 | 完整query/gallery；201/100按camera过滤；MSVR按同身份同时间段过滤；无reranking |

固定位置和投影与历史小邻域实现不同，且两端共同改变；因此本配对只解释9对128的读取支持差，不能把差值单独归因于偏移、投影或语义对应。完整读取后的槽位允许关注远处内容，原读出的4组只能称槽位组，不声称已定位真实空间部件。

## 核心验证与阶段门

1. CPU合同：两种网格的初始state逐张量一致、参数数目相同；支持范围外Patch不影响局部槽位但影响完整槽位；有限输出与形状。CPU使用线性算子代替Mamba，仅验证代数，不是生产训练证据。
2. 真实M0：每端真实训练loader的8批、真实Mamba和AMP；所有可训练张量至少一次非零梯度；冻结基线未变；保存重载输出误差≤1e-5。失败端停止，保留失败步和日志；不跳过batch或自动重试。
3. 正式六端：local/full×201/100/MSVR，共300个角色训练epoch。四GPU空闲即排队，无抢占。全部完整端后统一判断。
4. 验收：核对源代码/协议/初始化/checkpoint/距离SHA、完整50轮轨迹、同一个最高mAP点、CPU全图库复算fused/global/local；三数据集两端初始模型SHA和可训练参数量一致。

**后继投入门：**full−local在三数据集mAP均为正、R1均不下降，且201/MSVR的mAP均至少+0.5个百分点，才值得登记后继独立global-only和多seed验证。此门仅约束投入，不等于统计显著性或SOTA。失败不调整门，不搜seed挽救。
