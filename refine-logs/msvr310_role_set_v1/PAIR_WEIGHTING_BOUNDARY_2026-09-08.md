# 当前角色集合目标与集合度量、AP 目标的边界

2026-09-08，原 role-set Q1 执行代码仍绑定 26c9739。本文件是代码与原论文对照，不登记下一训练、不改变当前目标，也不推断未完成 Q1 的效果。

## 本次原文核对

Multi-Similarity 的 GPW 用 loss 对相似度的导数解释关系权重；其 MS 方法先按正负相对关系挖掘，再软加权。文中的三类 similarity 是同一表示空间内的自身及相对相似度，并非三个异构 encoder。它也分别实验了只挖掘后等权、只软加权的版本。依据：[作者原文 §3、§4.2、§5.1](https://arxiv.org/html/1904.06627)。CVF 论文页面本次返回 403，实际核对使用作者 arXiv HTML，未复制实现代码。

Smooth-AP 将 AP 的排序指示函数用 sigmoid 近似，正例排序与总体排序构成比值。温度决定有效梯度区域，作者讨论了候选规模对该区域覆盖的影响。这是对集合排名的近似，不是均值 Triplet 的别名。依据：[作者原文 §3、§4.1、§6.4、补充 §10](https://arxiv.org/html/2007.12163v2)。本轮没有采用论文实验参数或性能值作为项目结果。

## 当前代码实际改变的对象

`tools/msvr_role_set_relations.py:20-64` 使用 fused、CNN、Transformer、Mamba 的距离各提出一个最近负例，按位置去重。保留同一最难正例，在实际 fused 的未平方欧氏距离上平均 hinge；提议索引不反传。当前没有 MS 的相对边界挖掘与 soft weighting，也没有 AP 的正例排名分子/总体排名分母。

| 对象 | 当前 role-set v1 | MS / Smooth-AP 的直接区别 |
|---|---|---|
| 负关系选择 | 最多四个空间提议的位置并集 | MS 按正负相似度关系挖掘，不能将其“三种相似度”称为三角色提议 |
| 正关系 | 沿用唯一 hardest positive，保留原 tie 语义 | 当前不遍历所有正例的排名贡献 |

## 均值系数与梯度权重不能混写

下面仅为当前目标的局部数学展开：固定一个 anchor 的提议和极值索引，避开极值并列、hinge 零点及零距离。设选中负位置数为 K，激活项数为 A，单位 fused 向量相似度 s 对应 d = sqrt(2-2s)。当前单 anchor 目标为

L_i = (1/K) sum_n [d_p-d_n+0.3]_+。

在距离坐标中，对每个激活负关系有 dL_i/dd_n = -1/K，正关系有 dL_i/dd_p = A/K；在相似度坐标中，则有

dL_i/ds_n = 1/(K*d_n)，dL_i/ds_p = -A/(K*d_p)。

全 batch 均值还乘 1/64。这里没有把它当成新理论或参数梯度实测。实际 encoder 梯度仍需链式法则；并列时按当前代码的原 maximum/minimum 和 argmin 约定处理，不用这段光滑区推导覆盖非光滑点。

由此得到三个分析边界：第一，等 hinge 系数不等于等相似度导数或等 encoder 梯度；第二，未激活的新增项仍计入 K，可能降低原激活项权重；第三，同一状态下均值目标不大于原 hardest，不能将两种不同定义的 loss 数值直接比较为优化改善。这些都不能单独预测未见身份 mAP。
