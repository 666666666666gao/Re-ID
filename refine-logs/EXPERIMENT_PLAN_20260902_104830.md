# V14 Experiment Plan

**问题**：三专家已具备 query 级互补性，但 V13 点式 Router 监督近乎均匀且
跨 fold 不稳定，无法可靠改善 held-out 检索排序。  
**方法主张**：在同一 OOF teacher 坐标系内直接优化 cross-camera retrieval
regret，并以最坏 source fold 控制 Router 更新，可避免 V13 的目标错位。  
**日期**：2026-09-02

## Claim Map

| Claim | 为什么重要 | 最小可信证据 | 对应块 |
|---|---|---|---|
| C1（主） | V14 relational objective 比 source-selected fixed policy 更能跨 fit fold 迁移 | 每折 risk gain>0，AP/margin 不降，三项 identity-bootstrap 下界>0 | B1–B3 |
| C2（安全边界） | 增益不是跨 OOF 坐标混用或质量路由失效造成 | fold binding、Phase-A SHA、退化响应、missing=0、dev0/official0 | B1–B3 |
| Anti-claim | 不能把 Q1 写成完整路径 OOF、dev 增益、HFER 协同或 SOTA | receipts 明确 all-fit Router input / OOF teacher；未过门不运行 dev | 全部 |

## Paper Storyline

- 当前 must-run 只证明 Router objective 是否有效；不提前扩展论文故事。
- HFER、三创新点、正式消融、其他数据集和官方 test 全部延后到主 dev 达标
  以后。
- 不运行 baseline reproduction、多种子、温度/LR/epoch/margin/loss-weight
  扫描。
- 无 LLM/VLM/Diffusion/RL 组件；这里最合适的现代能力来自冻结 CLIP
  pretrained tail，强行加入 frontier 模块会偏离已定位的 Router 监督问题。

## Experiment Blocks

### B1：M0 public-seam contract

- **Claim tested**：fold-bound risk 与 exact deployment fusion 可正确反传，且
  不混合 OOF 坐标。
- **数据/任务**：纯合成 toy tensors，不读取 RGBNT201。
- **系统**：V13 fusion + V14 risk/comparator/gate helpers。
- **指标**：手算 risk delta、same-camera exclusion、fold binding rejection、
  参数梯度覆盖、missing mass、exact prefix/alpha parity。
- **设置**：新增最少 public seam；不改 V13 文件的既有行为。
- **成功标准**：全部测试通过；每个 Router 参数有 finite nonzero gradient。
- **失败解释**：实现合同错误；停止，不运行真实 cache。
- **成本**：CPU 数秒。
- **优先级**：MUST-RUN。

### B2：Q0 real-cache zero-step qualification

- **Claim tested**：真实 V13 paired cache 能提供合法、非退化且可微的 fold
  retrieval signal。
- **数据/任务**：571 fit-only queries、21 identities、3 folds；exact paired
  cache SHA `1cc499...15e27`。
- **系统**：seed42 初始化 V14 Router；optimizer 不构造或不执行 step。
- **指标**：每折 query/identity/cross-camera positive/negative 数；uniform 与
  9 fixed-slot risks；source minimax fixed slot；loss/gradient finite；全参数
  gradient coverage；Phase-A SHA；access counts。
- **成功标准**：三折均有合法正负样本；worst-fold loss finite；所有 Router
  参数 finite nonzero gradient；optimizer steps=0；SHA 不变；dev0/official0。
- **失败解释**：V14 目标在真实缓存上不可执行，封存方法。
- **成本**：RTX3090 预计 <1 分钟、<4 GiB。
- **优先级**：MUST-RUN。

### B3：Q1 sole seed-42 OOF Router qualification

- **Claim tested**：固定 V14 objective 能跨三个登记 fit folds 转移。
- **数据/任务**：相同 571 query 三折；每次两折训练、一折 held-out。
- **比较系统**：source-only minimax fixed slot 与 learned Router。held-out
  best fixed slot 仅 oracle diagnostic。
- **训练设置**：hidden128、AdamW、LR3.5e-4、V13 weight decay、100 epochs/
  fold、quality weight1、fixed alpha0.2；只训练 Router；seed42。
- **主指标**：held-out risk gain、replay AP gain、replay margin gain。
- **诊断指标**：Rank-1、V13 expected utility、action Top-1、held-out best-fixed
  oracle、质量权重响应。
- **成功标准**：三折 risk gain>0；三折 AP/margin gain≥0；三项 pooled
  identity-bootstrap 95% lower bound>0；质量/missing/SHA/access 门全通过。
- **失败解释**：固定 relational Router objective 无法可靠转移；立即封存，
  不 final refit、不 dev、不扫描。
- **成本**：依据 V13 的 300 steps/34.26s，预计 1–3 分钟、峰值约 3.5 GiB；
  新 cdist 风险可能略增但远低于 24 GiB。
- **优先级**：MUST-RUN。

### B4：conditional final refit + one dev

- **Claim tested**：通过 train-only 门的 Router 是否产生可部署主结果。
- **前置条件**：B3 全部门通过；否则本块不存在。
- **系统**：一次 all-fit Router refit + 冻结 Phase-A；不重训 baseline/专家。
- **指标**：baseline/fused/CNN/Transformer/Mamba mAP、Rank-1；访问计数、
  checkpoint SHA 与 strict reload parity。
- **成功标准**：fused mAP≥65；mAP 严格超过 Signal58.0109、V8B58.4050 和
  三分支；Rank-1 严格超过三分支；official0。
- **失败解释**：V14 最多是 train-fold objective 结果，不晋级 HFER/消融/
  official test。
- **成本**：Router refit 预计 <1 分钟；dev feature extraction/eval 预计数分钟。
- **优先级**：CONDITIONAL MUST-RUN。

## Run Order and Milestones

| Milestone | 目标 | Run | 决策门 | 预计成本 | 风险 |
|---|---|---|---|---|---|
| M0 | 实现最小 public seam | V14-TDD | 全测试 green | 20–40 分钟实现，秒级测试 | fold binding 写错 |
| Q0 | 真实 cache 零步信号门 | V14-Q0 | gradient/SHA/access 全过 | <1 GPU 分钟 | max 只激活一个 fold，但所有共享参数仍应有梯度 |

## Implementation Surface

只新增或最小修改以下文件：

- `modeling/trifusion/signal_preserving_v14.py`：fold-bound risk、minimax fixed
  slot、worst-fold regret 与 gate 数据结构；
- `tools/train_v14_fold_robust_router.py`：Q0/Q1/conditional refit 编排；
- `configs/RGBNT201/TriFusion-signal-preserving-v14-fold-robust-router-rtx3090.yml`；
- `tests/test_trifusion_signal_preserving_v14.py`；
- `tests/test_train_v14_fold_robust_router.py`；
- `docs/TDD_SEAMS.md` 仅登记新增 public seam。

复用 V13 Router、fusion、paired cache、quality cache、bootstrap 和 replay
metric；不复制 backbone，不修改数据集，不加入 fallback。

## Compute and Data Budget

- GPU：只在用户远端 RTX3090；本地 Windows 不训练/评估。
- 种子：仅 42。
- 数据：现有 RGBNT201 与 exact V13 paired cache；不下载新数据。
- 预估主门 GPU 时间：Q0+Q1 <5 分钟；条件 dev 总计预计 <20 分钟。
- 最大瓶颈：不是显存，而是 source-only policy 是否能在 held-out fold 保持
  risk/AP/margin 同向改善。

## Stop Rules

- M0/Q0 任一失败：只修实现错误；不改科学合同。
- Q1 科学门失败：封存 V14，不做任何同 family 扫描。
- Q1 通过但 dev<65或不胜分支：不进入消融/official；先做结果诊断并提出
  新的结构假设。
- 只有 dev 主门全通过，才计划 HFER 主阶段和论文消融。
