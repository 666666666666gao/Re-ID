# Research Proposal: Dense Triadic Relation Envelope Distillation（DTRED）

## Problem Anchor

- **Bottom-line problem**：在固定 RGBNT201 `141-fit / 30-dev`、seed42、单张
  RTX3090、`RERANKING=false` 协议下，让共享 Signal/CLIP 语义主干上的 CNN、
  Transformer、Mamba 三个异构专家形成可部署的深度协同，并把当前
  V8 Phase-B 的 `58.4050 mAP / 59.3939 Rank-1` 提升到至少 `65 mAP`。
- **Must-solve bottleneck**：V8 已证明三个专家存在显著 query-level Oracle
  互补，但 V12--V14 的 sample-local Router 无法跨身份预测最优专家，V15 的
  hidden exchange 伤害检索，V16 的 sparse two-peer teaching 在 Transformer
  三折均为零活动。必须把“专家互补”转成稠密、身份隔离、能泛化到单样本
  embedding 的监督，而不是继续调 Router 或稀疏阈值。
- **Non-goals**：不做 test-time graph/rank fusion 或 k-reciprocal reranking；不
  新增 DINO/SAM/VLM/完整 backbone；不重跑 baseline；不进行多种子、参数扫描、
  消融或 official test，除非冻结的主实验门先通过。
- **Constraints**：所有训练与评估只在远端 RTX3090；物理 batch B64/K8；只用
  seed42；保留 exact 3072D Signal output；V12 complete-path identity-OOF 仅用于
  train-only 资格门；30-dev 最多一次冻结终点评估；官方 test 在 dev 晋级前为0。
- **Success condition**：train-only 三折资格门证明 DTRED 相对 matched weight0
  在每折不劣、聚合 fused 至少 `+1.0 mAP`、identity-bootstrap 95% lower bound
  大于0且三个 corrected expert 聚合均为正；随后唯一 D1 no-reranking dev 达到
  `>=65 mAP`，并严格超过 exact Signal、V8 Phase-B 和三个 corrected branches。

## Technical Gap and Route Choice

已有系统并不缺强表示。V8 的 branch/residual Oracle 证明 CNN、Transformer、
Mamba 对不同检索关系各有优势，但固定融合几乎没有收益。失败证据进一步排除了
三类接口：sample-local Router 看不到 query-gallery 关系；hidden exchange 会破坏
检索几何；稀疏 hard teaching 无法稳定激活三支。

Test-time rank/graph consensus 最接近 Oracle，但属于 reranking，会改变冻结协议，
因此排除。DTRED 只在训练时读取三专家 pairwise relation，把关系互补蒸馏为每个
样本独立可计算的 embedding；推理仍是普通 forward、L2 normalization 和欧氏距离。

## Method Thesis and Contribution

DTRED 对每个 source-training pair 使用三种冻结专家关系构造单向包络：正 pair
至少达到最强专家的同身份相似度，负 pair 至多保持最强专家的异身份相似度。一个
共享低秩 triadic correction 同时更新三个 receiver 的表示，fused 与三 branches
共同接受包络约束。

主贡献是 **heterogeneous relation-envelope distillation into no-reranking
single-sample embeddings**。创新边界包括：

1. CNN/Transformer/Mamba 三种 inductive bias 共同定义 label-conditioned envelope；
2. one-sided constraint 只惩罚未达到包络，不惩罚超越 teacher；
3. 图库相关关系被压缩为无需测试图库交互的 embedding；
4. complete-path identity-OOF gate 要求三个 corrected receivers 共同获益。

max/min 运算、标准 hard mining、Signal prefix、ID/triplet 和共享几何增强不单独
宣称为创新。Signal protection 只是 fused 安全约束。

## Architecture

冻结 exact Signal 与 V8/V12 pretrained-tail experts。三支输出
`r_C,r_T,r_M in R^1536`。唯一新模块 `TriadicCorrection` 为：

```math
q_e=P_{in}(LN(r_e))\in R^{256},\qquad p_e=q_j\odot q_k,
```

```math
\delta_e=P_e(MLP([q_e,p_e,\bar q])),\qquad
h_e=Normalize(r_e+\delta_e).
```

`P_in`和MLP由三支共享，三个output projections保留receiver身份。最终：

```math
c=Normalize([h_C,h_T,h_M]),
```

```math
z_f=Concat(z_{Signal},||z_{Signal}||c),
```

```math
z_e=Concat(z_{Signal},||z_{Signal}||h_e).
```

模型同时输出 `baseline_only/fused/cnn/transformer/mamba`。没有 Router、attention
stage、second fusion head、sample alpha、memory bank 或 runtime fallback。

## Source-only One-sided Relation Envelope

每个 Q1 fold 的 teacher 与 gradient 只接触该 fold 的94个 source-training
identities。47个held-out identity labels只在final epoch完成后用于一次资格评价。

对合法 source pair：

```math
s^e_{ij}=\langle\hat r^e_i,\hat r^e_j\rangle,
```

```math
t^+_{ij}=\max_e s^e_{ij}\quad(y_i=y_j,c_i\ne c_j),
```

```math
t^-_{ij}=\min_e s^e_{ij}\quad(y_i\ne y_j).
```

全部 teacher tensor detach。对任一 corrected output `u`：

```math
E^+(u)=Mean_{P^+}[ReLU(t^+_{ij}-s^u_{ij})^2],
```

```math
E^-(u)=Mean_{P^-}[ReLU(s^u_{ij}-t^-_{ij})^2],
```

```math
E(u)=\frac12E^+(u)+\frac12E^-(u),
```

```math
L_{env}=\frac12E(f)+\frac16(E(h_C)+E(h_T)+E(h_M)).
```

正负集合独立求 mean；formal B64/K8 batch 必须同时包含合法正/负 pair，否则 M0
失败。外部 `L_env` 系数固定1.0。student优于teacher时hinge为0。

## Signal Protection and Total Objective

只对 fused 复用已经 formal 执行过的保护常数：

```math
L_{safe}=ReLU(m_S-0.02-m_f),\quad m_S\ge0.30.
```

总目标：

```math
L=L^f_{id+tri}+\frac13\sum_eL^{h_e}_{id+tri}
+1.0L_{env}+0.25L_{safe}.
```

ID label smoothing=0.1；triplet 对 L2-normalized embedding 计算；Signal、三
experts 和 relation teacher 均冻结。没有 branch safety subsystem。

## Why Pair-level Envelope Can Exceed Query-level Oracle

V8 branch Oracle 对每个 query 只能选择一个完整 expert output。DTRED 可让同一
query 的一个 positive pair 继承 CNN relation，而不同 negative pairs 分别继承
Transformer 或 Mamba relation，再由 student 学成一致的检索几何。因此
`64.785 mAP` 是高风险参照而不是 DTRED 的数学上限；是否能泛化必须由 Q1/D1
实证决定。

## Paired Q1 Contract and Receipts

DTRED 与 weight0 的 initial state、trainable names、seed、sampler indices、前8个
增强后 RGB/NIR/TIR tensor SHA、optimizer、batch 和 step 完全一致；唯一差别是
`L_env` 外部系数1或0。weight0只用于train-only机制归因，不是成功后的论文消融。

每折同run记录：

- source-training `t+` unique argmax 与 `t-` unique argmin 的 C/T/M count、
  fraction、tie fraction；
- fused/C/T/M 的 `E+`、`E-`、violation 与 satisfaction；
- DTRED 相对 weight0 的正负 violation 变化；
- corrected branch pairwise cosine、mAP、unique AP wins；
- source/heldout identity lists、核心文件和 checkpoint SHA、dev0/official0。

teacher-source distribution只作透明描述，不改变任何gate或超参数。

## Gated Execution

### M0 engineering gate

1. TDD覆盖one-sided方向、正负独立mean、固定scalar、detach与exact prefix；
2. real B64/K8 8-step capacity：全部trainable tensor有限非零gradient、overflow0；
3. fixed-batch100-step floor-aware overfit；
4. 每fold首8个hash-bound batch都有合法正/负pair，fused/C/T/M envelope路径均
   实际贡献gradient；
5. exact Signal和frozen experts SHA不变，dev0/official0。

### Q1 identity-OOF gate

三fold各20 epoch、seed42、final-only paired endpoints。全部满足才授权D1：

- 每fold fused mAP gain>=0；
- 571-query weighted aggregate fused gain>=+1.0 mAP；
- identity-cluster bootstrap10k 95% lower bound>0；
- CNN/Transformer/Mamba aggregate gain均>0；
- DTRED相对weight0的fused positive和negative violation均下降；
- paired/integrity/frozen/dev0/official0全部通过。

Q1只是train-only mechanism qualification，不能与30-dev 65门横向比较。

### D1 no-reranking main dev

仅Q1全门通过后，在141 fit identities上训练all-fit correction 20 epoch，seed42、
final-only、唯一一次30-dev。fused必须`>=65 mAP`且严格胜exact Signal、V8
Phase-B和三个corrected branches。失败即封存，不进行width/loss/LR/epoch/
checkpoint扫描，也不添加runtime fallback。

## Failure and Claim Boundaries

- envelope violation不优于weight0：不能归因DTRED；
- 任一corrected branch aggregate gain<=0：三方互促claim失败，停止D1；
- D1<65或不严格胜comparators：无部署/SOTA claim；
- D1成功前不做消融、多种子或official；成功后才设计最小必要性表和公平SOTA表。

## Compute

- M0约5--8分钟；
- Q1约35--50分钟；
- 条件D1约20--30分钟训练加3--5分钟dev；
